# S5 run-log design v3 (PR #104): two variants for an owner decision

Status: DESIGN ONLY. Base `6e1479c` on `stab/S5-run-log-telemetry`. The v2 text is kept at the scratchpad copy
`design-v2.md`. Two design rounds each grew the import protocol, so v3 puts two complete variants side by side:
- **Variant I**: import, with every round-2 fix (sections I.1 to I.9);
- **Variant C**: cutover, no import (sections C.1 to C.7).

Section X compares them honestly and asks the owner-level questions.

Common to BOTH variants (owner non-negotiables):
- the shared log `<git-common-dir>/ai-skills/ship-ticket/<T>.jsonl` is the single authoritative source for every normal
  reader and writer;
- there is no runtime multi-source union, no `excluded/`, and no sibling-worktree read in normal operation;
- the main checkout's pre-S5 log IS the shared log (its `--git-path` is the common dir), so main-checkout history is
  fully visible in both variants;
- REPAIR authority is unchanged: `carrier.mjs`, `review-auth/`, `isReservedTicket` and `ownDirIsShared` are
  byte-identical, and nothing in either variant writes `review-auth/` except the existing REVIEW-start copy;
- `quarantine` is extended (AC12) so that it clears every content-level writer-refusal state of the shared log, to a
  FIXED POINT, with sidecars and `log_loss`. The 64 MiB size refusal is explicitly out of AC12: capacity recovery is a
  documented manual archive step (section X residuals).

PR #104 is unmerged; nothing from it shipped. Shared logs, `excluded/` and `<T>.review-auth.jsonl` files from
1cce5af/6e1479c builds exist only in tests and local runs, and get no compatibility path.

## VARIANT I: import (complete, all round-2 fixes)

### I.1 Identities

- **Generation.** Each import source (one linked worktree's legacy `<T>.jsonl`) gets an immutable generation id `g`.
  - It is 16 random hex digits, persisted in that worktree's `migrated/<T>.json` the first time `migrate` runs.
  - A recreated worktree has a new gitdir, hence no manifest and a new `g`. Editing the source does not change `g`.
  - Collisions are detected: `migrate` refuses if the shared log already holds a valid commit for `g` whose
    `source_path` differs (64-bit space plus detection).
- **Qualified identities.** Every imported row is transformed deterministically; all of the following get the suffix
  `.from-<g>`:
  - `run_id`, `event_id`, and the metrics `review_execution` / `previous_review_execution`;
  - the row also gets `"imported_from": "<g>"`.

  So imported RUNS, intervals and review rounds can never merge with native S5 runs or with other generations.
  `buildRun`'s "last workflow outcome" and review grouping become per-source by construction (Codex 2).
  `candidate_id` stays a shared identity (it names a commit, not a run).
- **Over-long ids.** If any qualified id exceeds 128 characters or SAFE_ID, its INTERVAL is unimportable.
- **Engine and usage joins (eval).** An imported run `R.from-g` joins engine state, usage and attempts ONLY in the
  worktree that owns `g`, and only if that worktree's state file has `run_id == R`. Everywhere else imported runs have
  engine figures `unknown`. Documented loss.
- **Normalization (Codex 9).**
  - Comparison form: recursively key-sorted JSON of the transformed row.
  - Storage form: the canonicalJson of the transform.
  - The comparison is a MULTISET: a row that appears twice in a source stays two rows (a genuine duplicate is preserved
    and reported).

### I.2 Commit records and visibility

- **Commit record.** A start/end pair with all of these fields:
  - `run_id: 'legacy-import'`, `kind: 'activity'`, `name: 'legacy_import'`, `event_id: 'legacy-import.<g>.<n>'`;
  - metrics `{ generation: g, source_path, rows, rows_sha256, batch_from_bytes, batch_to_bytes, accepted: [..] }`;
  - no `imported_from`.

  A row is a commit record ONLY if all those fields validate (Codex 10). A pre-existing row that merely uses run
  `legacy-import` stays ordinary history.
- **Reserved names (AC15).** Every writer refuses:
  - run id `legacy-import` (case-insensitive);
  - name `legacy_import`;
  - event ids starting `legacy-import.`;
  - any id containing `.from-`, except the own-generation END mapping in I.4.

  These are refused in `start`, `end`, `event`, `close` and `batch`, so a commit record cannot be forged through the CLI
  (Opus N1).
- **Visibility (Opus N1, N2).**
  - Generation `g` is VISIBLE iff the multiset of rows carrying `imported_from: g` equals the union of the row sets
    covered by ANY valid commit records of `g` (batches never overlap; each covers its own `rows_sha256`).
  - When `g` is hidden, EVERY row whose `run_id` or `event_id` ends `.from-<g>` is hidden: the imported rows AND the
    S5 rows that ended them. No orphan end is ever exposed.
  - Hidden generations are reported as `import_incomplete(g)` by every reader. This is shared state, identical in every
    worktree.
- **The reserved run `legacy-import` is excluded from every count** (runs, aggregates, integrity events, eval) (Opus N5).

### I.3 `migrate --repo <wt> [--ticket T] [--accept-skipped-events] [--accept-torn-tail] [--accept-unimportable]`

1. **Pending manifest.** Create or keep `migrated/<T>.json` with `{state: 'pending', generation: g, source_path}`,
   written atomically (`writeStateAtomic`).
2. **Read the full source** (bytes B, sha H): its committed prefix, any torn tail, intervals, unimportable intervals,
   and S-04 pairs (skipped).
3. **Publish under the shared lock.** One `appendRows` call:
   - the guard recomputes the missing transformed rows of `g` against `before`;
   - it appends them plus commit record `n+1` covering exactly them, in one write;
   - `assertCleanLog` checks the whole file.
4. **Verify:**
   - fsync the shared file (ALSO on the no-op path; Codex 7);
   - re-read it, apply the visibility rule, and require `g` VISIBLE with exactly the expected multiset;
   - re-hash the source: it must still equal (B, H).
5. **Complete** only if all of these hold, each checked on EVERY status read (Codex 5, 7, 8):
   - `unimportable == 0`, or `--accept-unimportable` was given and the dropped intervals are listed;
   - no torn tail, or `--accept-torn-tail` was given and the torn bytes are recorded (Opus N4);
   - `skipped_events == 0`, or `--accept-skipped-events` was given and recorded;
   - `g` is visible in the shared log.

   Acceptances are MONOTONIC: once recorded, a flag stays in the manifest, and later runs keep it without the flag.
   Every path (no-op, acceptance-only) runs the full step 4.
6. **Changed source (Q2 as proposed by Opus).** A re-run after the source grew imports ONLY when the previously
   committed prefix `[0, batch_to_bytes)` is byte-identical. The new bytes become batch `n+1` of the SAME `g`.
   Otherwise status is `changed_incompatible` and nothing is imported (report only).

### I.4 Writers: legacy-started runs and continuation (Codex 1, 4; Opus N3)

- **Source ownership is resolved BEFORE lookup.**
  - Own generations: read from this worktree's manifest only.
  - Native lookup: `--run-id R --event-id a` in the shared log.
  - Own-generation lookup: `R.from-g`, `a.from-g` for the own `g`.
- **Ambiguity is refused:**
  - a native `R`/`a` AND an own-generation alias both exist → refuse `ambiguous`, naming both;
  - the user may pass the qualified ids explicitly, and only own-generation qualified ids are accepted;
  - a sibling's generation is never resolved.
- **`start a` in run R** while `a.from-<own g>` is an OPEN visible imported start → refused (Opus N3).
- **`end a`:** only own-generation, committed, visible, open imported starts are ended, with the qualified ids. A retry
  after that end exists gives "already ended".
- **Before import:** a start that exists only in the own unmigrated legacy log → refused with "run migrate" text
  (amended AC2). An own unmigrated legacy END for the id → refused.
- **Continuation identity.** A legacy run that continues in S5 continues as `R.from-g` in that worktree. New intervals
  of that run are written with the qualified run id, which the ownership resolution supplies for the own `g`.

### I.5 Quarantine to a fixed point (Codex 6, 11)

`quarantine` loops until a full pass finds nothing to move, bounded by the line count. Each pass:
- computes every writer-refusal reason: S-04 badness, legacy line errors, ticket mismatch, pairing breaks (orphan end,
  duplicate start, invalid pair: the later row), and imported rows not covered by a valid commit;
- moves those lines to one sidecar with a `log_loss` record.

The 64 MiB size refusal is excluded (documented manual archive).

### I.6 Readers (own status only, no sibling reads)

| Reader | Output |
|---|---|
| `summary` | figures = visible shared rows; `legacy: { status ∈ absent / unmigrated / pending / complete / complete_with_acceptances / changed_compatible / changed_incompatible / evidence_missing / unreadable, … }`; `import_incomplete` integrity warnings |
| `check` | `append_ready` and `migration_ready` (actual manifest target); `degraded` lists every non-clean own state; exit 1 if not `append_ready` or own `unreadable` |
| `eval` | `degraded[]` for every non-clean own state (`count: 'unavailable'` when unreadable) and every `import_incomplete` |
| integrity line | ` legacy=<status>`, ` degraded=import_incomplete(n)`; never the exit code |
| `lostSignal` | shared only, plus an `import_incomplete` count |
| carrier | unchanged |

### I.7 Invariants the Variant I tests must prove

1. No normal command opens a sibling's file.
2. The order of migrations of two sources never changes any figure (runs, outcomes, review rounds, eval joins), tested
   in both orders with conflicting outcomes.
3. A generation is either fully visible or fully hidden, its S5 ends included.
4. A commit record cannot be created by any CLI writer.
5. Every refusal is cleared by `quarantine` (except size); quarantine reaches a fixed point.
6. Completion ⇔ the I.3 step-5 conjunction, re-verified on every read.
7. Reimport only under the same `g` with a byte-identical prefix.
8. Ambiguous aliases are refused; a sibling's generation is never resolved.
9. An imported or shared-only REVIEW row never authorises; legacy authority is unchanged.
10. SIGKILL at every seam leaves a state that a re-run completes with exactly one visible copy.
11. Multiset semantics: a genuine duplicate is preserved.
12. A pre-existing run named `legacy-import` that is not a valid commit stays history.

### I.8 Size

- **Code:** about −330 (the union machinery) and about +650 (generation and manifest about 120, transform and
  normalization about 80, commit and visibility about 110, migrate about 150, ownership resolution and guards about 80,
  quarantine fixed point about 60, reader statuses about 50). Net about **+320**.
- **Tests:** about −250 and about +800 (the 12 invariant classes, real SIGKILL, conflicting-order matrices).
- **Estimated review risk:** high. Two rounds each found new majors in the protocol.

### I.9 Variant I residuals

- History is lost if a worktree is removed before migration.
- A crash leaves hidden partial batches until a re-run.
- TOCTOU between preflight and write.
- fsync cannot prove media durability.
- 64-bit generation space (with detection).
- Imported runs lack engine joins outside their own worktree.
- S-04 rows are not imported.
- Files are unsigned (never authorising).

## VARIANT C: cutover, no import

### C.1 Model

| Path | Normal readers and writers | Other access |
|---|---|---|
| shared `<common>/…/<T>.jsonl` | ALL reads and writes | — |
| linked worktree's legacy `<git-path>/…/<T>.jsonl` | NEVER read, except `legacy_present`: own worktree only, `lstat` plus a bounded read (at most 1 MiB, line count only, never parsed into figures) | carrier REPAIR read (byte-identical); explicit `run-log.mjs legacy` audit |
| `review-auth/` | unchanged | carrier |
| `migrated/`, `excluded/`, manifests, commit records | do not exist | — |

**History.** Pre-S5 legacy logs of linked worktrees stay untouched on disk as a read-only archive. Nothing rewrites,
copies or merges them. The main checkout's pre-S5 history is already in the shared log.

### C.2 Commands

- **`start`, `event`, `close`, `batch`, `quarantine`:** shared only. Pre-S5 semantics on one file, plus S5's
  timestamps, batch and authority copy, plus AC12's fixed-point quarantine.
- **`end`** whose start is absent from the shared log:
  - normal text when the own worktree has no legacy log: `event a has no start in run R`;
  - when `legacy_present > 0` in this worktree: `event a has no start in the shared log; this worktree has a pre-S5
    log (<path>, <n> lines). A run started there cannot be ended by this version: close it with the build that started
    it, or record that it was abandoned with "run-log.mjs abandon --repo <repo> --ticket T --run-id R"`.

    Zero rows are written. The content of the legacy log is NOT read; only its presence is used.
- **`abandon --repo --ticket --run-id R [--reason <enum>]`:** writes ONE shared terminal interval for run R.
  - The pair is `kind 'workflow'`, `name 'legacy_abandoned'`, `event_id 'legacy-abandoned'`, start = end = now,
    outcome `abandoned`, metrics `{ legacy_run: true, reason }`.
  - It is reserved: AC15 refuses that name and id in every other writer.
  - It is idempotent: an existing record returns as it is.
  - It never reads the legacy log and never writes `review-auth/`.
- **`legacy --repo <wt> [--ticket T]`:** the explicit read-only audit.
  - It prints the legacy rows of the worktree given by `--repo` (the operator names it), plus a summary computed over
    THAT file alone, labelled `scope: 'legacy-archive'`.
  - It is never combined with the shared log. ENOENT means `absent`; any other error is reported with errno.
- **Readers** (`summary`, `check`, `eval`, integrity line, `lostSignal`): shared only.
  - They add an own-worktree `legacy_present: { files, lines | 'unavailable', errno? }`.
  - `check` lists it in `degraded` (exit 0) and exits 1 only if the shared log is not append-ready.
- **Carrier:** unchanged.

### C.3 How C changes the approved AC2 (EXPLICIT DEVIATION; owner must choose)

- **Approved AC2:** "migration is required before ending a legacy-only run; an `end` whose start exists only in an old
  log is refused with a 'run migrate' hint."
- **Variant C:** there is no migration. A legacy-only run can NEVER be ended by S5. `end` is refused with the C.2 text.
  The run is either closed by the old build that started it (in that worktree, which still writes only its legacy log),
  or marked in the shared log by `abandon`.
- **The honest consequence.**
  - The legacy part of such a run (its phases and timings) is not in shared figures.
  - The run's S5 continuation (new intervals written after the upgrade under the same `run_id`) is in the shared log,
    so in shared figures that run shows only its post-upgrade part, plus `abandoned` if recorded.

### C.7 Variant C residuals: what is lost or not merged

1. Pre-S5 history of LINKED worktrees is not in any figure. It is visible only through `run-log.mjs legacy --repo <wt>`
   while that worktree exists, and is lost when it is removed (as in I without migration).
2. A run that spans the upgrade in a linked worktree is split. Its legacy part is in the archive, its S5 part in the
   shared log, and the legacy-started intervals can be closed only by the old build or marked `abandoned`. Timings of
   that run are partial in figures.
3. Pre-S5 S-04 measurement events in linked worktrees are not in figures (I also skips them).
4. An old build still running in a linked worktree keeps writing to its legacy log, invisible to S5. `legacy_present`
   grows there.
5. Shared-log damage blocks every worktree until `quarantine`; the 64 MiB size refusal needs a manual archive.
6. TOCTOU between preflight and write; fsync durability; unsigned files (never authorising).

## X. Comparison and recommendation

| Criterion | Variant I (import) | Variant C (cutover) |
|---|---|---|
| Owner non-negotiables (single authority, no union, no sibling reads, authority unchanged) | met | met |
| Approved amended AC2 ("migrate before end") | met as worded | DEVIATES: no migrate; `end` refused, `abandon` instead |
| Linked-worktree pre-S5 history in figures | yes, after `migrate` (per-source runs) | no: archive plus `legacy` audit only |
| Main-checkout pre-S5 history in figures | yes | yes (it is the shared log) |
| Code delta vs 6e1479c | about +320 net | about −265 net |
| Test delta | about +550 net | about −150 net |
| New protocol surface (commit records, generations, visibility, aliasing, acceptance) | large; each round found new majors | none |
| The five-round defect class (coupling, arrival order, silent errors, preflight mismatch) | mitigated by more invariants | removed by construction (one source); quarantine and preflight remain |
| Remaining review risk | high | low |
| Data at risk on worktree removal | until migrated | the archive only (never in figures) |

**Recommendation: Variant C.** It removes the defect class instead of guarding it, deletes code, and keeps every owner
non-negotiable except the exact AC2 wording. Choose Variant I only if linked-worktree pre-S5 history must appear in
shared figures, and accept about +320 lines of code and another review round of the protocol.
