# vapt effectiveness measurement

One measurement run of the control catalog, with its rules, inputs, scorer and report. Start
with [`REPORT.md`](REPORT.md).

| File | What it is |
|---|---|
| `prereg.json` | The rules: what is counted, how cases are picked, which sentences the report may use. Fixed before any run. |
| `manifest.json` | Hashes of the rules and data files, where those hashes were posted, who saw what, and the limits. |
| `storecraft-facts.json` | Facts written for the 24 development cases. Fact values only. |
| `storecraft-judgments.json` | Two judges' yes / partial / no label for every development case and control. |
| `corpus2-index.json` | The 24 public advisories that were kept, and every advisory that was skipped with the rule that excluded it. |
| `corpus2-facts.json`, `corpus2-judgments.json` | The same two kinds of data for the public cases. |
| `results.json` | Generated by `score.mjs --write`. Never edited by hand. |
| `REPORT.md` | The report. Its results block is generated by `score.mjs --report REPORT.md`. |
| `score.mjs` | The scorer. It uses the one evaluator in `../../controls.mjs`. |
| `build-corpus2.mjs` | Picks the public advisories by the rule in `prereg.json` and fetches their code on demand. |
| `prep-local.mjs` | Builds the local-only inputs for the development cases from an audit record and a repository. |

`../../effectiveness.test.mjs` checks that the file hashes equal the manifest, that the catalog
is the frozen one, that `results.json` and the report block regenerate exactly, and that the
data files hold nothing but fact values and labels.

## Rules for changing anything here

- These results belong to one catalog hash. If `../../controls.json` changes, the test fails:
  the results are stale and the measurement has to be run again under a new `prereg.json`.
- Do not edit a data file. A new run gets new files and new posted hashes.
- No product code, path, commit text or finding text belongs in this folder.
