# S5 archive helper proposal (design only, NOT implemented): `run-log.mjs archive-legacy --repo <wt>`

Why it exists: three rounds showed that a documented shell copy of git metadata cannot be made safe by construction. The
failures were a user-supplied name, string-compared paths, a followed symlink, and promotion of a legacy REVIEW row
into main REPAIR authority via `../review-auth`. The helper replaces the removed runbook. Until it is approved, the interim
rule in observability.md holds: keep the worktree, or save the `legacy` audit output.

## Command
`run-log.mjs archive-legacy --repo <wt>`. There are no other inputs: no name, no source, no destination.
- It prints one JSON line `{ status: 'PASS'|'REFUSED', archive, files, bytes, sha256_file, reason? }`.
- Exit 0 only on PASS.
- It never removes the worktree. The operator runs `git worktree remove` after reading PASS.

## (i) Source: derived, never a user path
- The program resolves `SRC = ownLogDir(--repo)` (`git rev-parse --path-format=absolute --git-path ai-skills/ship-ticket`).
  It REFUSES when that equals `commonLogDir` (the main checkout) or is not under `<git-common-dir>/worktrees/<id>/`.
- Every entry is `lstat`ed:
  - regular files are copied;
  - a directory is descended only if it is a real directory (`review-auth/` is NOT copied; see v);
  - symlinks, FIFOs, sockets and devices are refused, and the refusal is listed with the path; nothing is ever followed.
- Files are opened with `O_RDONLY|O_NOFOLLOW|O_NONBLOCK`. The size is bounded per file (64 MiB, the run-log cap) and in
  total (256 MiB); over the limit means REFUSED, never a partial archive.
- `lstat` is checked before and after each read (size, mtime, ino equal). A concurrently changing source is REFUSED.

## (ii) Destination: derived, validated, exclusive
- `NAME` = the `<id>` directory name of the worktree's gitdir (`<git-common-dir>/worktrees/<id>`). git creates it, and it
  must match `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`, else REFUSED. It is never user-supplied, has no `/`, and is never
  `.`/`..`.
- `ROOT = realpath(<git-common-dir>)/ai-skills/ship-ticket/archive-legacy`.
  - It is created with `mkdirSync` (not recursive) when absent. If present it must be a real directory (`lstat`, not a
    link) whose `realpath` equals ROOT.
- `DST = ROOT/<NAME>.<UTC compact timestamp>`, created with `mkdirSync` (fails if it exists, so it is O_EXCL by
  nature). Every file inside is created with `openSync(..., 'wx')` (O_EXCL), so nothing is overwritten.
- Containment proof, computed on `realpath`s:
  - DST is strictly under ROOT;
  - DST is never equal to or under the shared log dir's files: ROOT is a SUBDIRECTORY of it, and nothing writes outside
    ROOT;
  - DST is never under or equal to any `review-auth` directory, SRC, `<common>/worktrees`, or `<common>` itself;
  - SRC is never under DST.
  A failure is REFUSED before the first write.

## (iii) Copy and verify (Node fs only, no shell)
- Bytes are copied per file through `read`/`write` (O_EXCL target), the target is fsynced, then the directory is fsynced.
- `<DST>.sha256` records `sha256  <relative path>` per file, computed from the SOURCE bytes read.
- Verify: re-open every DST file, re-hash it, and compare with the recorded value. Any mismatch is REFUSED (DST is left,
  marked `<DST>.INCOMPLETE`, never reused).

## (iv) Non-effects
- The source is never modified or deleted.
- The worktree is never removed.
- Nothing is ever written to the shared log, to `review-auth/`, to the engine files, or outside DST, `<DST>.sha256` and
  `<DST>.INCOMPLETE`.

## (v) REPAIR authority invariant
- The carrier reads exactly `<own --git-path>/ai-skills/ship-ticket/review-auth/<T>.jsonl` and, in a linked worktree,
  `<own --git-path>/ai-skills/ship-ticket/<T>.jsonl` (carrier.mjs, unchanged).
- The archive lives at `<common>/ai-skills/ship-ticket/archive-legacy/<NAME>.<ts>/...`. That path is never equal to
  `<main --git-path>/ai-skills/ship-ticket/review-auth/<T>.jsonl`, nor to any `<T>.jsonl` directly in a git-path dir,
  because it is two directory levels deeper.
- `review-auth/` subtrees of the source are NOT archived (authority copies are per-worktree state, not history). The
  audit gets them read-only via `legacy`.
- Every reader lists tickets only as `*.jsonl` directly in the log dir, so `archive-legacy/` is never a ticket source.
- Test: after archiving a legacy log that contains a REVIEW start `(T1, R, review-1)`:
  - `verifyReviewExecution(main, {ticket:'T1', run_id:'R'}, 'review-1')` still throws;
  - `summary --all` from every worktree lists no new ticket and no new row.

## (vi) Test plan (RED-first; temp layouts only; never `/` or real repos)
1. **Adversarial worktree ids:** `..x`, `-x`, a space, a newline, unicode, a name of exactly 64 or 65 characters
   (REFUSED or handled per the regex).
2. **Adversarial sources:**
   - the own `ai-skills/ship-ticket` as a symlink to an unrelated dir;
   - a symlinked file, a FIFO, a file over the limit;
   - a source changed mid-copy (lstat ino or size);
   - a relative `--repo` and a subdirectory `--repo` (derived paths identical).
3. **Adversarial destinations:**
   - `archive-legacy` as a symlink (to SRC, to `review-auth`, to `/tmp`), as a regular file, or as a dir with an
     existing `<NAME>.<ts>`;
   - main checkout `--repo`.
4. **Authority:** the REVIEW-row promotion attempt above, and an archived `review-auth/` (not copied).
5. **fs spy** (the existing preload): every write-class call (`openSync` with `w`/`a`/`x`, `mkdirSync`, `writeFileSync`,
   `renameSync`, `symlinkSync`) targets a path under ROOT. Reads touch only SRC and git metadata. A failed child or an
   empty trace fails.
6. **Verification:** a flipped byte in DST after the copy (via a test seam on the verify read) gives REFUSED plus
   `.INCOMPLETE`.
7. **Idempotence:** a second run creates a new timestamped DST and never touches the first.
8. **Mutants:** each guard removed or weakened (name regex, the containment check on realpaths, O_NOFOLLOW, the
   review-auth exclusion, wx, verify) must turn a named test red.

Size estimate: about 140 lines (new `lib/run-log-archive.mjs`) plus about 15 (command wiring and docs) plus about
260 test lines. It reuses `readArchive`'s lstat and O_NOFOLLOW pattern; no new dependency.

## Acceptance criteria (proposed)
- **AC16:** `archive-legacy` writes nothing outside `<common>/ai-skills/ship-ticket/archive-legacy/<derived-name>.<ts>`
  plus its `.sha256` (and `.INCOMPLETE` on failure); proven by the fs spy.
- **AC17:** it never follows a symlink and never copies a non-regular file; it refuses the main checkout, unsafe ids,
  oversize, and a source that changes.
- **AC18:** PASS only after every file is re-read and its hash matches.
- **AC19:** no archived byte can authorise REPAIR or appear in any figure (carrier and reader paths above; test).

**Plan-text amendment:** delivered capability gains "a linked worktree's pre-S5 history can be preserved by
`run-log.mjs archive-legacy` (raw, verified copy under the common dir) before the operator removes the worktree".
Non-goal "no migration/copy/delete of old logs" becomes "no migration, no merge, no deletion; only an explicit
verified raw copy into `archive-legacy/`".

## (vii) Manual steps and residuals
- **Manual:** reading PASS, then `git worktree remove`; any later export or restore of the archive. The helper never
  restores.
- **Residuals:**
  - an operator can still `rm -rf` the worktree first;
  - TOCTOU between the final lstat and the copy is narrowed (before/after checks), not eliminated;
  - files in the archive are unsigned (anything that can write `.git` can alter them; `.sha256` detects accidental
    change only);
  - `review-auth/` copies are deliberately not archived; if needed for audit, they must be kept by leaving the
    worktree.
